# Data Model: Complete UI Modules

**Feature**: `002-complete-ui-modules`  
**Store**: PostgreSQL 17.x  
**Rule**: Every business row belongs to one tenant directly or through a tenant-qualified immutable parent. Direct `tenant_id` is preferred on high-volume, searchable, asynchronous, exported, or security-sensitive rows.

## Global Conventions

### Identifiers and Tenant Keys

- New domain identifiers are UUIDs generated by the application or database-approved helper.
- Existing text identifiers remain supported during incremental migration; APIs treat identifiers as opaque.
- Tenant-owned tables use `tenant_id NOT NULL` and tenant-qualified unique keys such as `(tenant_id, id)` or `(tenant_id, natural_key)`.
- Tenant-to-tenant references are prohibited. Composite foreign keys include `tenant_id` where practical; service validation and adversarial tests cover legacy references until constraints are migrated.
- No business operation falls back to a default tenant.

### Time and Versioning

- Timestamps are `timestamptz` in UTC; user-facing scheduling retains the originating IANA timezone.
- Mutable aggregate roots include `created_at`, `updated_at`, and monotonic `version` for optimistic concurrency.
- Append-only ledgers never update business fields. Corrections are new events linked to the superseded event.
- Soft lifecycle uses explicit status/archival timestamps rather than ambiguous deletion flags.

### Actor, Correlation, and Audit

Every mutation records actor or service identity, tenant, correlation ID, reason where required, result, and before/after references. Domain state, audit evidence, and asynchronous intent are committed atomically.

### Sensitive Data

- Secrets store encrypted versions and opaque references; cleartext is never persisted in ordinary domain rows.
- Sensitive exports and media use opaque storage references, expiry, digest, size/type, retention class, and access evidence.
- AI provider payloads are not canonical records. Store minimized structured inputs/evidence references and redacted outputs according to policy.

## Existing Foundation and Migration Treatment

The current schema already contains:

- Core: `users`, `sessions`, `companies`, `contacts`, `leads`, `conversations`, `conversation_messages`, `activities`, `settings`.
- Identity/governance: `roles`, `user_roles`, `audit_events`, `secrets`, `secret_versions`.
- Messaging: `channels`, `channel_credentials`, `channel_sessions`, `webhook_events`, `outbox_jobs`, `delivery_events`, `failed_jobs`.
- Operation: `teams`, `team_members`, `queues`, `queue_members`, `conversation_assignments`, `internal_notes`, `sla_policies`, `conversation_sla`, `routing_rules`.
- Content/configuration: `tags`, `conversation_tags`, `templates`, `template_versions`.
- Early workflow/reporting: `automation_rules`, `automation_runs`, `privacy_requests`, `retention_runs`, `metrics_rollups`.

These tables are evolved in place. Migration first adds/backfills tenant keys and compatibility columns, validates conflicts, then adds tenant-qualified constraints and indexes. No table's existence alone establishes feature completion.

## 1. Workspace, Identity, and Authorization

### Tenant

Fields: `id`, `name`, `slug`, `status`, `locale`, `timezone`, `plan`, `created_at`, `updated_at`.

Invariants:

- `slug` is globally unique and immutable after external use.
- Status: `active`, `suspended`, `archived`.
- Suspended tenants cannot create external side effects but retain authorized read/recovery access.

### User and Tenant Membership

`users` holds global login identity. `tenant_memberships` holds `tenant_id`, `user_id`, `status`, `display_name`, `locale`, `timezone`, `capacity`, `availability_status`, `joined_at`, `deactivated_at`, `version`.

Unique: `(tenant_id, user_id)`.

Membership status: `invited -> active -> suspended -> deactivated`; reactivation is explicit and audited.

### Role, Capability, and Role Assignment

- `roles`: tenant-scoped custom/built-in role metadata and immutable role key.
- `role_capabilities`: `role_id`, `resource`, `action`, scope ceiling, optional conditions.
- `user_role_assignments`: tenant, membership, role, effective/expiry time, assigner.
- `object_grants` only where exceptional delegation is needed; normal policy derives from tenant/team/ownership.

Built-in role keys: `agent`, `supervisor`, `manager`, `marketing`, `admin`, `privacy_auditor`, `integration_developer`.

Unique: `(tenant_id, role_key)` and one active identical assignment per membership/role.

### Team and Membership

Extend `teams` and `team_members` with status, capacity override, availability, effective dates, and role within team. A queue membership references the tenant-qualified team or user.

### MFA Factor and Recovery

- `mfa_factors`: membership, type, encrypted secret/public credential, label, state, enrolled/verified/last-used timestamps.
- `mfa_recovery_codes`: factor or membership, one-way code hash, used timestamp.
- `mfa_challenges`: short-lived challenge hash/reference, purpose, attempts, expiry, completion.

Raw factor secrets and recovery codes are never redisplayed after enrollment.

### External Identity

`external_identities`: tenant, issuer, subject, membership, verified email metadata, last login, status. Unique `(tenant_id, issuer, subject)`. Provider claims do not store or directly grant local capabilities.

### Session

Extend `sessions` with tenant/membership, assurance level, rotated-from, last-seen, revocation reason, and security version. Privilege or factor changes invalidate insufficient sessions.

## 2. Audit, Secrets, Quotas, and Feature Policy

### Audit Event

Extend `audit_events` with `tenant_id`, actor/service identity, action, resource type/id, outcome, reason, before/after JSON or digests, IP/network context, correlation/trace IDs, previous event hash, event hash, and timestamp.

Audit rows are append-only. Index `(tenant_id, created_at DESC, id DESC)`, resource lookup, actor lookup, and correlation lookup.

### Secret and Secret Version

Tenant-qualify `secrets`; keep versions immutable. `secrets.active_version_id` points to exactly one non-retired version. Unique `(tenant_id, purpose, name)`. Rotation changes the active pointer transactionally and logs a redacted event.

### Feature Flag and Assignment

- `feature_flags`: tenant, key, enabled, rollout percentage, policy JSON, version.
- `feature_flag_assignments`: flag, subject type (`team`, `user`), subject ID, enabled override.

Evaluation is deterministic from tenant/subject and flag version.

### Quota Policy and Usage Bucket

- `quota_policies`: tenant, operation, limit, interval, burst, enabled.
- `quota_usage`: tenant, operation, subject key, bucket start, count, version.

Unique `(tenant_id, operation, subject_key, bucket_start)`; increments are atomic.

## 3. Channels, Messaging, and Inbox

### Channel and Credential

Tenant-qualify existing channel/session/credential rows. Channel natural uniqueness is `(tenant_id, provider, name)`. Credential validation state remains separate from channel enabled state.

### Webhook Event

Extend with tenant, correlation, normalized event type, payload digest, retention class, lease fields, failure classification, and dead-letter timestamp. Unique `(tenant_id, channel_id, provider_event_id)`.

State: `pending -> processing -> processed`; retryable failure returns to `pending`; terminal path `processing -> dead_letter`; recovery creates an append-only recovery event and a new lease attempt without erasing history.

### Contact Identity

See CRM section. Inbound sender resolution uses `(tenant_id, identity_type, normalized_value)`.

### Conversation

Fields: tenant, contact, channel, queue, owner, status, priority, subject, last-message cursor/time, snoozed/follow-up timestamps, opened/closed timestamps, optimistic version.

Status: `open <-> closed`; `open -> snoozed -> open`; archived is terminal for normal operation. Assignment and status changes also append events.

Indexes:

- `(tenant_id, status, updated_at DESC, id DESC)`.
- `(tenant_id, owner_user_id, status, updated_at DESC, id DESC)`.
- `(tenant_id, queue_id, status, updated_at DESC, id DESC)`.
- Partial indexes for unassigned and due follow-up/SLA.

### Conversation Message

Fields: tenant, conversation, direction, sender/actor, channel, provider/client message IDs, type, body, template version, reply reference, status, sent/received timestamps, search vector, correlation.

Unique provider inbound key and outbound client key per tenant/channel. Status transitions are monotonic except explicit reconciliation: `queued -> sending -> sent -> delivered -> read`; failures record attempts and may recover to sending with the same idempotency key.

Full-text index is tenant-filtered in the query and indexed on the search vector.

### Attachment

Fields: tenant, message or draft, opaque storage key, filename, media type, size, digest, scan state/result, encryption/key reference, expiry, retention class, created actor/time.

Scan state: `pending -> clean | infected | rejected | error`. Only `clean` attachments can be delivered or downloaded.

### Assignment Event

Extend/replace mutable-only assignment with append-only `conversation_assignment_events`: conversation, from/to user/team/queue, reason, actor, correlation, created time. Current assignment remains materialized on conversation.

### Presence and Edit Lease

`conversation_presence`: tenant, conversation, membership, viewing/composing state, heartbeat, expiry. Unique current `(tenant_id, conversation_id, membership_id)`. It is ephemeral and may be purged after expiry; it never authorizes access.

### Internal Note and Macro

- Notes: tenant, conversation, author, body, visibility scope, created/edited metadata; edits retain versions.
- Macros: tenant/team, name, structured actions, active/version state. Actions are validated and authorized individually.

### Queue, Routing, SLA, Calendar, Follow-up

- Extend queue with status, capacity/default SLA and routing strategy.
- Routing rules have priority, typed criteria/action, active version, effective dates.
- `business_calendars` and `calendar_intervals/holidays` define IANA timezone-aware service periods.
- SLA instances record policy version, due timestamps, pause durations, breach state, and events.
- Follow-ups record conversation, owner/queue, due time, status, completion/cancellation reason.

Routing claim uses transactional locking and appends a decision event. A retried event cannot assign twice.

## 4. Customer 360 and CRM

### Contact

Extend contact with tenant, normalized name/phone/email, company, language, timezone, lifecycle stage, lead source, owner/team, status, merge target, version. Phone/email global uniqueness is not assumed; tenant identity records determine collisions.

### Contact Identity

Fields: tenant, contact, type (`phone`, `email`, `external`), normalized value, provider/source, verified state/time, primary flag. Unique active `(tenant_id, type, normalized_value, provider)` where applicable.

### Consent Event and Suppression

- `consent_events`: append-only tenant/contact/channel/purpose, action (`grant`, `withdraw`, `record_evidence`), source, policy/text version, occurred time, evidence reference, actor/correlation.
- `suppressions`: current tenant/contact or normalized identity, scope/purpose/channel, reason, effective/expiry times, source event.

Outbound eligibility always checks current suppression plus consent history. Withdrawal creates suppression atomically.

### Custom Field Definition and Value

Definitions: tenant, key, label, entity type, data type, constraints/options, searchable, active, version. Values: tenant, definition, entity type/id, one canonical typed value representation, version. Unique `(tenant_id, definition_id, entity_type, entity_id)`.

Allowed types include text, number, boolean, date/time, enum, and reference. Values must satisfy the definition version active at write time.

### Tag and Tag Assignment

Tenant-qualify tags with unique `(tenant_id, name)` and color validation. Generalize assignment to contact/conversation/opportunity with tenant-qualified entity checks and append audit on apply/remove.

### Opportunity and Pipeline

- `pipelines`: tenant, name, active.
- `pipeline_stages`: tenant/pipeline, name, position, closed/won flags.
- `opportunities`: tenant, contact, owner/team, pipeline/stage, title, value/currency, expected close, status, version.
- `opportunity_stage_events`: append-only before/after stage, value, reason, actor/time.

### External Record Reference

Tenant/contact, provider/integration, record type, external ID/version, display summary, status, last sync. Unique `(tenant_id, integration_id, record_type, external_id)`.

### Unified Timeline

`timeline_events` is an append-only projection keyed by tenant/contact, event time, stable source type/id, summary metadata, visibility. Unique `(tenant_id, source_type, source_id, source_version)`. It references canonical domain records; it is rebuildable.

### Merge Job

- `contact_merge_previews`: short-lived tenant/source/target, conflict plan, counts, creator, expiry.
- `contact_merge_events`: committed source/target, before/after references, conflict resolutions, actor/time.

Commit locks both contacts, revalidates preview/version, re-points permitted references, preserves identities and history, marks source merged, and records one transaction.

### Import, Export, and Bulk Job

Common job root plus:

- Import: file reference, mapping version, options, total/valid/invalid/duplicate counts; row outcomes with row number, normalized identity, action, error codes.
- Export: query/filter definition, columns, status, artifact reference/digest, expiry, requester, retrieval count.
- Bulk: selection snapshot/query definition, action, bounded target count, per-object outcome.

Artifacts are tenant-scoped, expiring, and audited on generation/retrieval.

## 5. Segments and Campaigns

### Segment and Version

- `segments`: tenant, name, description, status, active version, owner/team, refresh policy.
- `segment_versions`: immutable expression tree, exclusion expression, schema version, creator/time.
- `segment_memberships`: tenant, segment/version, contact, eligibility state/reason, computed time, source contact version.

Unique `(tenant_id, segment_id, contact_id)` for current materialization and immutable history by version/run where retained.

Expression nodes permit typed logical operators and allowlisted field/operator/value triples. Maximum depth/node count/value count are bounded.

### Segment Refresh

`segment_refresh_runs`: tenant, segment/version, state, cursor, counts, started/completed/error. State follows shared job semantics. Preview uses the same compiler but stores only bounded samples and aggregate counts.

### Campaign

Fields: tenant, name, segment version, template version, channel, category, timezone, scheduled time, status, quota/throttle policy, creator/approver, version.

Status:

```text
draft -> pending_approval -> approved -> scheduled -> running -> completed
  |            |                |          |          |
  +----------> cancelled <------+----------+----------+
running -> paused -> running
running|paused -> cancelling -> cancelled
```

No transition out of terminal `completed` or `cancelled`.

### Campaign Recipient and Attempt

Recipient fields: tenant, campaign, contact, destination identity, eligibility snapshot/reason, scheduled time, state, stable idempotency key. Unique `(tenant_id, campaign_id, contact_id, destination_identity_id)`.

Before transport, eligibility is rechecked. Attempt records provider reference, state, failure class, times, and correlation. Delivery/read/opt-out events attribute through recipient/attempt.

## 6. Automation and Integrations

### Automation Rule and Version

Extend `automation_rules` into aggregate root with tenant, name, status, active version, owner, kill-switch state. `automation_rule_versions` stores immutable trigger, typed conditions, typed actions, timeout/schedule, fallback/handoff, schema version.

Status: `draft -> active -> paused -> archived`; activation points to an immutable validated version. Rollback activates a prior version and appends an event.

### Automation Execution and Action Result

Execution: tenant, rule/version, trigger event type/id, idempotency key, dry-run flag, state, condition trace (bounded), start/end, error. Unique `(tenant_id, rule_version_id, trigger_event_type, trigger_event_id, dry_run)`.

Actions have ordinal, typed input digest, proposed/effective output, state, idempotency key, provider/job reference. Dry-run action state is `proposed` and cannot enqueue side effects.

### Integration and Credential

`integrations`: tenant, provider/type, name, status, configuration without secrets, credential reference, health, version. Unique `(tenant_id, type, name)`.

### Sync Record and Attempt

Sync record: tenant, integration, domain type/id, external type/id/version, direction, state, conflict policy/state, last success/error. Attempt: immutable request digest, operation key, outcome, provider metadata, times.

Unique external key and operation idempotency key per tenant/integration.

### API Credential and External Webhook

- API credentials store prefix/identifier, one-way secret hash or encrypted signing key, scopes, tenant, expiry/revocation, last-used metadata.
- Incoming/outgoing webhook registrations store endpoint, event allowlist, signing secret reference, status, and network policy.
- Webhook deliveries use shared jobs and immutable attempts.

## 7. Knowledge and AI

### Knowledge Article and Version

- Article: tenant, title, owner/team, status, active version, valid-from/to, tags, version.
- Article version: immutable body/source metadata, checksum, language, creator/time.
- Access policy: article/version, subject type/id or role/capability, effect, effective dates.
- Chunk/index entry: tenant, article version, ordinal, content digest, searchable text/vector reference if enabled, freshness time.

Status: `draft -> review -> published -> superseded | archived`. Only published, currently valid, authorized versions are retrieved.

### AI Policy and Evaluation

- AI policy: tenant, purpose, provider/model reference, prompt/policy versions, redaction policy, limits, enabled/rollout state.
- Evaluation corpus: versioned cases and expected safety/quality labels, with sensitive fixtures synthetic or controlled.
- Evaluation run/result: policy/model/corpus versions, metrics, failures, evidence digest, release linkage.

### AI Invocation, Suggestion, Feedback

Invocation records tenant, purpose, actor/service, policy/model versions, redacted input digest, evidence references, state, latency, usage/cost, safety disposition, correlation. It does not store chain-of-thought.

Suggestion stores structured output and references. Feedback state: `pending -> accepted | edited | rejected`, with actor/reason/time.

### Tool Action and Handoff

Tool action stores typed tool/version, validated input digest, authorization decision, confirmation requirement/time, idempotency key, state, result reference. Irreversible tools cannot enter `executing` without confirmed state.

Handoff package stores conversation, summary/evidence refs, proposed/completed actions, recipient queue/user, status, and audit correlation.

## 8. Privacy and Governance

### Privacy Request and Subject Match

Extend `privacy_requests` with tenant, subject identity, request type, verification state, due time, status, legal-hold decision, assigned operator, version. `privacy_subject_matches` records systems/entities considered and confidence/verification.

Status:

```text
received -> identity_pending -> verified -> in_progress -> completed
                                      |           |
                                      +-> denied  +-> partially_blocked
any nonterminal -> cancelled
```

Denial/partial block requires reason and policy evidence.

### Privacy Step and Artifact

Steps are per system/action with state, attempt history, before/after references, and error. Export artifacts are encrypted/opaque, expiring, access-limited, and audited. Delete/anonymize uses domain-specific handlers and preserves legally required audit evidence.

### Retention Policy, Legal Hold, and Run

- Policy: tenant, data class, duration, action, active version, legal basis.
- Legal hold: tenant, scope/subject/resource, reason, authority, effective/released dates.
- Retention run: policy version, dry-run flag, candidate/held/processed/error counts, state.
- Retention item: resource, decision, hold reference, outcome.

Dry-run and execution use the same selector; execution rechecks hold immediately before effect.

### Supplier and Transfer

Supplier: tenant, name, purpose, countries, contact, status, review dates. Subprocessor/transfer rows record data categories, destination, mechanism, retention, effective dates, evidence references.

### Incident and Escalation

Incident: tenant, title, severity, status, detected time, owner, impact, regulatory deadline, version. Events capture triage, containment, notification decision, communication, resolution, and postmortem. Timers/escalations are shared jobs.

## 9. Reporting and Operations

### Metric Definition and Event

- Metric definition: stable key/version, description, numerator/denominator, dimensions, time semantics, percentile rules, effective dates.
- Metric event: tenant, definition/event type, occurred time, dimensions, numeric/duration value, source type/id/version, correlation.
- Rollups: tenant, definition version, time bucket, dimensions, aggregates and percentile sketch/reference, computed time.

Unique source event prevents double counting. Fixed fixture reconciliation compares raw events, rollups, UI, and export.

### Report and Export

Report definition stores allowed dimensions/measures/default filters. Report run stores immutable selected definition versions, filters, timezone, status, row count, artifact/expiry for exports.

### Alert and System Health

- Alert rules: tenant/system scope, metric/condition/window, severity, destinations, status.
- Alert instances/events: state, first/last observed, acknowledgement, resolution.
- Worker heartbeats: worker type/instance, release hash, last seen, current lease counts.
- Release records: artifact hash, source hash, migration set, activated/rolled-back times.

### Common Job, Attempt, Dead Letter, Recovery

`jobs`: tenant, type, schema version, payload reference/JSON (no secrets), idempotency key, priority, state, available time, attempts/max, lease owner/token/expiry, cancellation request, parent/correlation, timestamps.

Unique `(tenant_id, type, idempotency_key)`.

`job_attempts`: immutable attempt number, lease token, worker/release, start/end, outcome, error class/code.

`dead_letters`: job, terminal reason, payload digest, dead-letter time, recovery status.

`recovery_actions`: job/dead-letter, action (`retry`, `reconcile`, `cancel`, `discard`), actor, reason, idempotency key, outcome.

State:

```text
queued -> leased -> running -> succeeded
   ^         |         |
   |         +-> queued (retryable/expired lease)
   |                   +-> failed -> queued (bounded retry)
   |                              -> dead_letter
queued|leased|running -> cancelling -> cancelled
```

Fenced lease token is required for worker completion. Cancellation and kill-switch checks occur before each externally visible effect.

## Referential and Deletion Rules

- Tenant deletion is not a cascade operation in production; it is a governed privacy/retention workflow.
- Users/memberships referenced by audit/events use `SET NULL` or immutable actor snapshots, never destructive cascade of evidence.
- Aggregate children such as unpublished draft versions may cascade only when no audit/execution reference exists.
- Published versions, delivery attempts, consent, campaign/automation executions, privacy steps, audit, incidents, releases, and recovery evidence are retained or anonymized according to policy, not hard-deleted casually.
- Contact merge redirects references transactionally and marks the source as merged; it does not erase source evidence.
- Channel/integration disablement preserves event and attempt history.
- Artifact bytes may expire while metadata/digest and access evidence remain per policy.

## Index Strategy

All high-volume access paths lead with `tenant_id`:

- Current-state lists: `(tenant_id, status, updated_at DESC, id DESC)`.
- Job claims: `(state, available_at, priority, id)` plus tenant/type operational indexes; partial indexes for claimable jobs.
- Expiring leases/follow-ups/artifacts: partial due-time indexes.
- Idempotency and provider IDs: tenant-qualified unique indexes.
- Search: tenant-filtered GIN text indexes and tenant-leading metadata filters.
- Timeline/audit/events: `(tenant_id, entity_id, occurred_at DESC, id DESC)`.
- Campaign recipients: campaign/state/scheduled time claim index.
- Metrics: tenant/definition/bucket/dimension indexes matched to allowed report queries.

Index additions require representative query-plan evidence and write-cost review.

## Validation Rules

- Phone numbers normalize to E.164 when country context permits; raw input is retained only where policy allows.
- Email is trimmed and normalized for comparison without incorrectly rewriting provider-local semantics.
- IANA timezone, locale, currency, language, MIME type, file size, URLs, and enum values are allowlisted/validated.
- Money uses integer minor units plus ISO currency, never floating point.
- Segment depth/nodes, automation actions, import rows, bulk targets, exports, media, and provider payloads have explicit limits.
- Template variables must match the immutable approved template version.
- Campaign/automation schedules store UTC execution plus originating timezone and daylight-saving resolution.
- State transitions use expected current version/state and reject stale writes.
- JSON metadata has bounded schemas; arbitrary SQL, scripts, URLs, credentials, and executable content are prohibited.

## Migration Order

1. Add migration lock/checksum governance and representative snapshot fixture.
2. Establish/validate tenants and backfill tenant keys on existing tables.
3. Add tenant-qualified unique keys and foreign keys after conflict reports are empty.
4. Extend identity, memberships, roles/scopes, MFA, external identity, audit integrity, feature flags, and quotas.
5. Extend messaging/inbox and add media, events, pagination/search, routing/SLA, presence, notes/macros, follow-ups, and common jobs.
6. Extend contact 360, consent/suppression, custom fields, opportunities, timeline, merge/import/export/bulk.
7. Add segments, memberships/refresh, campaigns, recipients, and attempts.
8. Version automation and add execution/action ledgers, integrations, sync, API/webhook credentials.
9. Add knowledge/version/ACL/indexing and optional AI policy/evaluation/invocation/tool/handoff records.
10. Extend privacy and add retention/legal hold, suppliers/transfers, incidents/escalations.
11. Add metric definitions/events/reports/alerts/heartbeats/releases.
12. Build indexes concurrently where deployment safety requires it, validate constraints, run clean-install and upgrade suites, then retire compatibility columns only in a later release.

Each step is independently rerunnable and must preserve the previous live version until activation and rollback compatibility are proven.
